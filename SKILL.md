# Reelcraft — запись голоса → вертикальный ролик

Нормы проекта — `CLAUDE.md` в корне проекта reelcraft, **прочитать первым
шагом** (темы, роли и модель каждого шага, константы канала, правила темпа
1–28, банки, QA, чистка).
Этот файл — только порядок работы.

Проект: `<ПУТЬ_К_ПРОЕКТУ>` — все команды ниже выполняются **из этой папки**.

> ⚠️ Строку выше заполняет установка (`INSTALL.md`, шаг 9): вместо
> `<ПУТЬ_К_ПРОЕКТУ>` ставится абсолютный путь папки конвейера — например
> `/Users/me/reelcraft` или `/d/projects/reelcraft`. Скилл живёт в домашней
> папке агента, а не в репозитории, и без этой строки он не знает, где лежит
> проект. Не заполнено — спроси человека и впиши, прежде чем что-то запускать.

Оболочка: на macOS и Linux любая, на Windows — **Git Bash** (не PowerShell:
скрипты конвейера на bash). Чем на Windows подменены macOS-утилиты и какие
грабли там вылезают — `tools/WINDOWS.md`.

**Тема по умолчанию — Sticker Light** (`library/light-theme.md`). Фирменная
зелёная **Emerald** (`library/emerald-theme.md`) — по словам «зелёная»,
«изумрудная», «фирменная», «как обложки». Тёмная
adaptive (`library/adaptive-theme.md`) или две темы — только если автор назвал
в запросе; обе темы равноправны. Сборка автономна: вопросов по ходу нет,
остановок нет — от inbox до готового файла. Два исключения: (1) сессия идёт
на слабой модели как главной → перед сторибордом остановиться и сказать
автору (творческое ядро на слабой модели даёт слабый ролик); (2) вопрос в
конце, перед чисткой.

## Голос и бренд автора — читать до любого текста

Ролик — это выход наружу, значит действует общий публичный голос канала, а не
«нейтральный диктор». Источники правды лежат в другом корне, в волте:

| Что | Файл |
|---|---|
| Публичный голос: как звучит твой текст наружу | твой файл голоса (заведи, если нет) |
| Бренд и палитра канала (из неё собираются темы) | твой файл бренда |
| Позиционирование и аудитория | твой файл позиционирования |

**Этих файлов у тебя может ещё не быть — тогда заведи их до первого ролика.**
В комплекте лежит скилл профиля (`.claude/skills/profile/SKILL.md`, установка —
`INSTALL.md`, шаг 9б): он берёт интервью и собирает заметку `voice` — как
звучит твой текст наружу. Без неё сценарий получится «средним», и это самое
заметное отличие чужого ролика от твоего: механика одинаковая, а слышно, что
говорит не тот человек.

Читать **перед** тем, как написать хоть строчку текста: сценарий под озвучку,
заголовки на плашках, чип над CTA, подписи в кадре. Ключевое из voice.md,
что ломается чаще всего: никаких подводок и «в этом ролике мы рассмотрим» —
первая фраза уже несёт содержание; ошибку подаём шуткой, не покаянием;
всегда оба слоя — «я сам наступил» и «вот рабочий результат».

Вычитка субтитров (шаг 3) — тоже сюда: Whisper иногда «причёсывает» живую
речь в канцелярит, возвращать к тому, как сказано.

## Конвейер

1. **Звук.** `./prep.sh` для файла из `inbox/` (−14 LUFS, ×1.2, чистка).
   Вход уже обработан ранее → `SPEED=1.0 ./prep.sh …`. Результат `inbox/NAME-prep.*`.

2. **Слот.** `scripts/queue-add.sh inbox/NAME-prep.mp4 NN` — номер ЯВНО
   (параллельные сессии, раздел «Параллельная сборка» в CLAUDE.md).
   Whisper large-v3-turbo с глоссарием `scripts/whisper-glossary.txt`
   (в комплекте — термины ИИ-ниши; подставь свои, Whisper путает именно
   те слова, которые для твоей темы ключевые).
   Даёт `queue/video-NN/`: `audio.wav`, `transcript.json`,
   `captions.generated.ts`, `meta.txt`.

   > **Шаги 3 и 4 запускаются ОДНИМ сообщением, параллельно** — три субагента
   > сразу. Они независимы: вычитка правит текст в слоте, опись читает банки,
   > футаж смотрит клипы. Последовательный запуск был чистой потерей времени
   > (правка 2026-10-07). Режиссёр ждёт все три отчёта и только потом садится
   > за сториборд.

3. **Вычитка — субагент `reel-transcript`.** `transcript.json` целиком;
   `captions.generated.ts` построчно — Whisper всё ещё может врать на
   терминах; тексты править, тайминги не трогать. Новый термин → дописать в
   `scripts/whisper-glossary.txt`. Разметить `hl:'mark'` и `hl:'red'`.
   Режиссёр принимает отчёт и решает спорные места.

4а. **Опись банков — субагент `reel-banks`.** Шесть банков из CLAUDE.md
   (иконки брендов + общие пиктограммы `icons/generic/`, Lottie,
   персонаж/стикеры, компоненты, SFX + стоп-лист, BGM + анти-повтор) +
   хуки/приёмы/BGM двух прошлых роликов из `library/used-log.md` +
   сториборды активных слотов. На выходе сводка «что взято / отказ с
   причиной» по каждому банку. Недостающие иконки —
   `node scripts/fetch-icons.mjs <бренды>` сразу. Сториборд без секции
   «Ассеты из банков» не готов.

4б. **Живой экран — субагент `reel-footage`** (отдельно от описи: здесь не
   перечисление, а решение «этот кадр отвечает на эту фразу»). Покадровый
   просмотр **каждого** клипа-кандидата, добыча скринов под конкретные биты,
   чек покрытия с колонкой «видео или статика». Отказ «цифры не совпадают»
   не принимается (правило 27 — клип под маской). На выходе по каждому кадру
   — **цели наезда числом `x, y, w, h`**, замеренные в ассете: это вход и для
   `PageCam`, и для рамки `TargetBox` (правило 28).

5. **Сториборд (режиссёр, творческое ядро)** → `queue/video-NN/storyboard.md`:
   - первая строка — тема ролика (light по умолчанию / adaptive /
     две темы → две ветки постановки, adaptive первой);
   - биты речи (хук / цифра / перечисление / как работает / связка / финал);
   - на каждый бит 2–3 кандидата из `library/INDEX.md`, сверка записей в
     `index-*.md` (grep по имени), у выбранных — карточка и demo TSX
     (demo — истина по параметрам);
   - анти-повтор: хук не повторяет два прошлых ролика, приём один раз за ролик;
     наезд PageCam по скрину анти-повтору не подчиняется (правило 19);
   - **живой экран** (правило 27): минимум один скрин/скринкаст из банка или
     добытый, с наездом; чек покрытия с колонкой «видео или статика»; цифры
     не совпали → клип под маской, цифра типографикой;
   - **цель каждого наезда и её рамка** (правило 28): цель пишется числами
     `x, y, w, h` из отчёта `reel-footage`, рядом — режим (`frame` или
     `spotlight`), кадр появления (в КОНЦЕ движения камеры) и `pad`. Цели
     «словами» в паспорте больше не допускаются: по ним рамка ложится на
     соседний текст;
   - **сверка видеоряда с речью:** начало каждой сцены сверить с окном слова
     в `transcript.json`. Это арифметика, и делать её надо ЗДЕСЬ, до вёрстки:
     сдвиг видеоряда на бит был главным блокером video-01, а после вёрстки он
     стоит лишний круг «правка → черновой рендер → контактный лист»;
   - adaptive (если заказана) — мини-спек темы в сториборд;
   - строка дуги энергии (`library/energy-arc.md`);
   - таблица сцен `| сцена | кадры @30 | бит | приём (карточка+demo) | что происходит |`
     + переходы + проверка «куда смотреть» по секундам; 8–12 сцен на 40–45с,
     накопитель только как приём (правило 23);
   - правила темпа и композиции 1–28 применяются здесь; у каждого носителя
     в паспорте размер и координаты числом (правило 16);
   - **все величины числами — и геометрия, и динамика** (правило 16):
     длительность фазы в кадрах, `scale from → to`, кадры появления и ухода.
     Относительных формулировок («растяни», «увеличь») в паспорте быть не
     должно: каждая из них стоит круга «правка → рендер → контактный лист»;
   - SFX-таблица: ЦЕЛЕВОЙ КАДР ПИКА относительным якорем
     (`SCENES[n].from + k`, голое число — брак), файл, пик из
     `sfx/CATALOG.md`, volume по формуле, `durationInFrames`, зачем.
     В код кадр попадает только через `sfxFrom()` — поправки на лаг сэмпла
     и смещение дорожки вносит он (CLAUDE.md «Время SFX»);
     BGM-трек с volume;
   - паспорт верстальщику: композиция, файлы, компоненты из `src/lib/`
     (Captions, Character `swapMode="dip"`, Bgm, CTACard, PageCam, TargetBox,
     FlowNode, DottedLink, MacWindow), пути к demo. Образец сантехники —
     `engine/README.md` + `src/videos/demo/`; сцены прошлых роликов — только
     как образец кода, не постановки.

6. **Вёрстка — субагент `reel-build`.** `engine/src/videos/video-NN/` + ассеты
   в `engine/public/videos/NN/` + регистрация в `Root.tsx` (перечитать перед
   правкой, блок перед якорем, `fps={FPS}` = 30). Общие компоненты
   импортировать из `src/lib/`, demo читать перед каждой сценой. Каждый наезд
   закрывается `TargetBox` по числам из паспорта (правило 28).
   Проверки: `node scripts/lint-scenes.mjs NN` = 0 ERROR, `npx tsc --noEmit`,
   затем **свой рендер и машинная приёмка**: `./scripts/render.sh <CompositionId>`
   → `./scripts/qa-auto.sh <out.mp4>` = 0 находок. Машинные правила (12, 20,
   21, 26) верстальщик чинит сам, пока ролик у него в руках; перепроверка —
   рендером диапазона `--frames=A-B`, не всего ролика. Что требует смены
   постановки — не чинит, а выносит в отчёт режиссёру.
   Кадры глазами не смотрит.

   > **Почему рендер переехал сюда (правка 2026-10-12).** Эти четыре правила
   > ловил терчек, и каждая находка стоила круга «терчек → правка →
   > перерендер» — 15–25 минут на арифметике, которую считает скрипт.
   > Заодно отменён черновой рендер: замер показал, что `scale 0.4` идёт
   > столько же, сколько чистовик (узкое место — прогон React в браузере, а
   > не пиксели), то есть ролик рендерился дважды без выигрыша. Рендер
   > теперь один, он же идёт терчеку и в сдачу.

7. **Терчек — чистый субагент `reel-qa`, единственный визуальный проход.**
   Вход: **путь к уже отрендеренному ролику** (шаг 6), сториборд, правила
   1–28, `../video-shotcraft/skill/references/{aesthetic-rules,final-review}.md`.
   Своего рендера у терчека нет.
   1) `./scripts/qa-sheet.sh auto <видео> 70` — сетка одним взглядом;
   2) `./scripts/qa-auto.sh <видео>` — контрольный прогон (верстальщик уже
      закрыл эти правила; находка здесь означает, что его правка сломала
      соседнее место);
   3) в полном размере — только 2–3 подозрительных кадра.
   Обязательные точки: кадр 0 как обложка; **синхрон речи и видеоряда по
   окнам слов из `transcript.json`**; текст на тайле 360px; дуга; живой экран
   есть и читается в конце наезда; **рамка цели стоит и не залезает на
   соседний текст (правило 28 — смотреть в полном размере, не на тайле)**;
   середина переходов контрастна; караоке не поверх носителя; SFX не
   обрублены; приватность.
   Отчёт «код ✓/✗ + кадр», без «в целом хорошо». Режиссёр смотрит тот же
   лист, блокеры чинит, находки перепроверяет замерами.

8. **Правки режиссёра и сдача.** Блокеры терчека чинятся, перепроверяются
   **рендером диапазона** (`./scripts/render.sh <Comp> out/chk.mp4 --frames=A-B`,
   ~1 мин); ролик целиком пересобирается только если правки задели несколько
   сцен. Готовый файл — тот же, что смотрел терчек, пересобранный после
   правок: `./scripts/render.sh <CompositionId>`, всегда версия с BGM.
   Лимитер сразу (команда в CLAUDE.md), `astats` Peak ≤ −0.5 dB,
   `volumedetect` окном речи и окном после речи. Финал → папка из
   `CHANNEL.outputDir` (`engine/src/channel.ts`), имя
   `video-NN-reelcraft-light.mp4` (adaptive: `-<герой>`, фолбэк `-noir`).

   > **Шаг 9 запускать ОДНИМ сообщением с финальным рендером** (правка
   > 2026-10-12): лог приёмов и коммит не зависят от того, досчитался ли
   > рендер, а рендер — единственное, что здесь занимает минуты. Ждать его,
   > чтобы потом дописать строку в used-log, — потеря трёх минут на ровном
   > месте.

9. **Пост-рендер — субагент `reel-wrap`.** Приёмы, хук и BGM ролика →
   `library/used-log.md`. Опись ролика для монтажного стола —
   `engine/src/videos/video-NN/workbench.ts` по образцу
   `engine/src/videos/demo/workbench.ts` (ни одного своего числа: всё
   импортируется из data-файлов ролика; устройство —
   `engine/src/lib/workbench.tsx`). Коммит файлов своего ролика явными путями.

   > После сдачи сказать автору одной строкой, что ролик можно доводить
   > руками: `./scripts/workbench.sh NN` — таймлайн в браузере, где кадр
   > двигается без правки кода (CLAUDE.md «Монтажный стол»).

10. **Чистка — тот же `reel-wrap`.** `scripts/save-storyboard.sh NN` (линт уже сделал) → спросить
    одной строкой «всё окей → чищу слот и рендеры?» → после «да»
    `scripts/clean-out.sh NN`, `queue/video-NN/`, `inbox/_raw/NAME.*`,
    `inbox/_done/NAME-prep.*`. `engine/public/videos/NN/` и готовые файлы в
    папке вывода не трогать никогда.

## Расход лимитов (замерено 2026-10-17)

За сутки на два ролика ушло **529,8 млн входных токенов и 3217 запросов** —
80% недельного лимита. Разбор показал, что дело не в рендере (25 минут на всё)
и не в размере файлов: стоимость = **число запросов × размер контекста в
каждом**, и те же 3217 запросов дают ~4,5 часа чистого ожидания модели. Это
же и ответ на «почему ролик делается пять часов вместо полутора».

- **Один ролик на сессию, без исключений.** Два ролика в одном контексте дают
  два сжатия контекста, и каждое заставляет перечитывать сториборды заново.
- **Шаг конвейера запускается ТОЛЬКО своим агентом.** `general-purpose` и
  `claude` на шагах 3, 4а, 4б, 6, 7, 9, 10 запрещены: у них нет паспорта шага,
  нет тормоза и нет запрета смотреть кадры глазами.
- **Агент оборвался или вернул пустой отчёт — НЕ перезапускать его и не
  подменять другим агентом.** Агенты пишут результат на диск, а не только в
  отчёт: сначала посмотреть, что уже сделано (`git status`,
  `node scripts/lint-scenes.mjs NN`, `ls engine/src/videos/video-NN/`), и
  доделать остаток режиссёром. Цена нарушения замерена: 2026-10-17 агент
  вёрстки умер на лимите сессии, подмена на `general-purpose` стоила
  **260 млн токенов — 49% расхода за сутки**, и оба подменных прогона вернули
  пустой отчёт.
- **Бюджет ролика — 150 млн входных токенов.** Замер:
  `python3 scripts/token-report.py` (сутки) или `--session <id>`. Вышли за
  бюджет — это находка для разбора в `library/used-log.md`, а не норма.
- **Команды склеивать.** Проверки идут одним вызовом через `&&`
  (`node scripts/lint-scenes.mjs NN && (cd engine && npx tsc --noEmit)`),
  независимые вызовы — в одном сообщении. Каждый лишний вызов инструмента это
  отдельный запрос, тянущий весь контекст заново.
- **Один файл не читается целиком дважды.** Перечитывание — только нужным
  диапазоном (`sed -n 'A,Bp'`). Пруф: терчек прочитал `scenesEmerald.tsx`
  (7k токенов) девять раз за один прогон.

Число шагов агента при этом **не сокращается** — замер показал, что это и есть
работа: у `reel-footage` нормальный прогон это 70–148 вызовов, у терчека
37–110. Экономить надо размер контекста на шаге, а не число шагов.

## Грабли

- Первый рендер в свежем node_modules докачивает headless-браузер ~93 МБ — не прерывать.
- Ошибки команд читать целиком, не `tail -1`.
- Лишние стиллы через `npx remotion still` не снимать: контактный лист.
- Рендер всегда через `scripts/render.sh`: он сам считает число воркеров по
  свободной памяти (константа 3 была страховкой при открытом Chrome; на
  свободной машине это вдвое медленнее, чем надо). Закрытый браузер на время
  рендера реально ускоряет сборку.
- У каждого запуска рендера есть постоянная цена ~40 с: Remotion каждый раз
  собирает бандл. Поэтому пять перепроверок по диапазону дороже, чем кажется,
  — правки лучше копить и проверять пачкой.
- Терчек тоже ошибается — замер главнее отчёта.
- Замер хвоста: `-ss` перед `-i`, иначе volumedetect показывает mean всего файла.
