# .codex/ — вторая голова конвейера

Тот же конвейер, но для **Codex** вместо Claude Code. Правила, пути и проверки
живут в `CLAUDE.md` и `.claude/` и остаются источником правды; здесь только
перевод под другого агента: свои навыки, свои описания субагентов с моделями и
образец конфигурации.

| Что | Файл | Зачем |
|---|---|---|
| Конфигурация проекта | `config.toml` | модель, политика подтверждений, песочница. **Образец — прочитай и поправь под себя** |
| Навык сборки ролика | `skills/reelcraft/SKILL.md` | обёртка над `.claude/skills/reelcraft/SKILL.md` |
| Навык радара тем | `skills/reels-radar/SKILL.md` | то же для `radar/` |
| Навык сценария | `skills/reels-script/SKILL.md` | текст под озвучку между радаром и сборкой |
| Субагенты этапов | `agents/reel_*.toml` | каждый читает свой `.claude/agents/reel-*.md` и переводит требования |

## Как поставить

Codex читает `AGENTS.md` в корне проекта сам — он уже на месте. Дальше:

1. **Открой `config.toml` и поправь две строки:** `model` (та, что у тебя
   доступна) и `writable_roots` (твоя папка вывода роликов, та же, что
   `CHANNEL.outputDir` в `engine/src/channel.ts`).
2. **Прочитай блок `developer_instructions`.** Это постоянное разрешение
   агенту работать без повторных вопросов на время сборки. Удобно, но решение
   твоё: не согласен — убери строки или поставь
   `approval_policy = "untrusted"`.
3. Применяется конфигурация так, как это описано в документации твоей версии
   Codex (конфиг проекта либо слияние с `~/.codex/config.toml`). Ставить
   навыки в домашнюю папку, как для Claude Code, здесь не нужно.

## Если ты работаешь только в Claude Code

Папку можно просто не трогать — на сборку роликов она не влияет. Удалять её
тоже незачем: описания субагентов в ней полезны как второй взгляд на то, какой
этап чего требует.
