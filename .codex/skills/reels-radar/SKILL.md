# Радар конкурентов в Codex

Перед прогоном прочитай `.claude/skills/reels-radar/SKILL.md`, `docs/РАДАР-ПЛАН.md`, `radar/accounts.json`, свой файл голоса (voice.md`, `content/strategy/positioning.md`, `content/shorts/_index.md`, `content/shorts/ideas.md`. Исходный навык задаёт метрику, отсев, формат карточек и остановку после выбора тем. Не переписывай его ради Codex.

Используй существующие `radar/fetch.py`, `radar/rank.py`, `radar/run.sh`, `radar/pull.sh` и локальный Whisper. На Windows для `.sh` нужен `C:/Program Files/Git/bin/bash.exe` и `tools/env.sh`. Сырые ответы остаются в `radar/raw/`, шортлист и транскрипты — в `radar/out/`, карточки тем — в свой файл с темами роликов, новыми сверху. Старые темы не удаляй; сверяй с `_index.md`, чтобы отличить запасные от уже взятых.

Apify — внешний платный сервис. Перед первым вызовом установи объём по `accounts.json` и `python radar/fetch.py --dry`, сообщи примерный максимум результатов и стоимость. Если пользователь уже прямо поручил новый прогон, это разрешение действует; не спрашивай повторно. Повторы ограничены `radar/run.sh`, не запускай новые платные попытки вручную вне этого лимита.

Для каждого доступного кандидата определи тему, форму хука, структуру, **свой подтверждаемый угол** и причину принятия или отсева. Не выдавай тему по одному заголовку или ролику без звука за проверенную расшифровкой. В финале покажи все тематические направления прогона: принятые, спорные и отсеянные с причиной. Остановись на выборе автора: сценарий, запись и сборка ролика начинаются только после его решения.

Не меняй `CLAUDE.md`, `.claude/`, существующий код радара и его форматы ради адаптации к Codex. Если текущая сессия не может писать в vault, запроси доступ к прежнему пути вместо создания второй очереди.
