# INSTALL — развёртывание конвейера reelcraft

**Это инструкция для агента, а не для человека.** Отдай её своему кодовому
агенту (Claude Code, Codex, Cursor) командой:

```
Установи конвейер по инструкции INSTALL.md в этом репозитории.
```

Дальше агент читает этот файл и ведёт установку сам, спрашивая человека только
там, где без него нельзя: данные канала, выбор темы оформления, скачивание
музыки.

> Это единственная инструкция установки: три платформы, проверка на каждом
> шаге и разбор поломок, которые на Windows вылезают там, где на macOS всё
> проходит гладко.

---

## Инструкция агенту: как себя вести всю установку

- **Веди человека по шагам, по-русски, простым языком.** Он может быть новичком
  в терминале: объясняй, что делает команда, **до** того как её запустить.
- **Не пропускай проверки в конце шагов.** Шаг не прошёл проверку — чини его,
  а не иди дальше. Пропущенная проверка всплывёт через три шага, и чинить
  придётся вслепую.
- **Ничего не удаляй за пределами папки проекта.**
- **Предупреждай про объём заранее.** Скачивания больше 100 МБ (модель
  распознавания — 1,5 ГБ, зависимости движка — 500 МБ, headless-браузер —
  93 МБ): скажи, сколько весит и сколько примерно ждать.
- **Личные данные (шаг 7) спроси одним блоком вопросов**, не по одному.
- **Ничего не выдумывай за человека.** Числа подписчиков, названия, хендлы —
  только те, что он назвал. Это правило 17 конвейера, и оно же общее правило
  канала, под который конвейер собран.
- **В конце покажи короткий отчёт:** что установлено, что осталось руками,
  какая первая команда для первого ролика.

Полная установка — **40–90 минут**, из них большая часть — скачивания. На
Windows ближе к 90: там дополнительно ставится инструментарий внутрь проекта
и накладываются патчи монтажного стола.

## Шаг 0. Определи платформу и скажи человеку правду

Первым делом выясни, на чём работаем:

```bash
uname -s    # Darwin = macOS, Linux = Linux, MINGW64_NT… = Windows + Git Bash
```

| Платформа | Статус | Что недоступно |
|---|---|---|
| **macOS** | ✅ основной путь | — |
| **Linux** | ✅ работает | забор записей из Диктофона (`--voice`), `caffeinate` |
| **Windows 10/11** | ✅ работает **нативно**, через Git Bash | — (но установка длиннее: см. ветку W) |
| **iPhone / iPad** | ❌ **конвейер не ставится** | всё |

### Про iPhone скажи прямо, не обходи вопрос

Конвейеру нужны Node.js, ffmpeg, Python, whisper.cpp и headless-браузер для
рендера. На iOS не запускается ни одно из этого — не из-за недоработки
конвейера, а из-за устройства системы: сторонние среды исполнения там
недоступны.

Роль iPhone в этом конвейере реальна, но другая:

- **на входе** — диктофон: человек пишет голос на телефон и отправляет файл
  на компьютер (AirDrop, облако, мессенджер) в папку `inbox/`;
- **на выходе** — просмотр готового MP4 и загрузка в TikTok, Reels, Shorts.

Если у человека **только** iPhone и никакого компьютера — установка
невозможна. Скажи это сразу и не начинай: честный отказ дешевле трёх часов,
которые упрутся в стену.

### Про WSL на Windows

Не предлагай WSL. Конвейер развёрнут и проверен **нативно**, и причина не в
удобстве: правило 27 требует живого экрана в кадре (настоящий скриншот или
запись окна программы), а из WSL скриншоты окон Windows не снять. Ставим в
Git Bash.

## Шаг 1. Проверь, что стоит в системе

```bash
node -v; npm -v; ffmpeg -version 2>&1 | head -1; python3 -V; git --version
```

Нужно: **Node.js 20+**, **ffmpeg**, **Python 3.9+**, **git**.

Чего нет — доставь по своей платформе.

**macOS** (Homebrew):

```bash
brew install node ffmpeg git
```

**Linux** (Debian/Ubuntu):

```bash
sudo apt update && sudo apt install -y ffmpeg git python3 python3-pip
# Node 20+ из репозитория дистрибутива часто старый — ставь через nodesource:
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash - && sudo apt install -y nodejs
```

**Windows:** ffmpeg и whisper ставятся **внутрь проекта** на шаге W1, в систему
их тащить не надо. Здесь проверь только Node, Python и git:

- Node.js 20+ — [nodejs.org](https://nodejs.org), установщик LTS;
- Python 3 — с [python.org](https://python.org), **с галкой «Add Python to
  PATH»**. Проверь, что это настоящий Python, а не заглушка Microsoft Store:
  `python -V` должен напечатать версию. Команда `python3` на Windows почти
  всегда ведёт в заглушку — это нормально, прослойка проекта её перекроет;
- Git for Windows — вместе с **Git Bash**, в нём и работаем.

Две библиотеки Python: **Pillow** — авто-QA (склейка контактного листа) и
заглушки персонажа и CTA-карточки; **numpy** — замеры звука
(`scripts/sfx-peaks.py`, `scripts/audio-offset.py`, `scripts/rc_audio.py`):

```bash
python3 -c "import PIL, numpy; print('PIL+numpy ok')" \
  || python3 -m pip install --user Pillow numpy
```

**Проверка шага:** все пять команд отвечают версиями, печатается
`PIL+numpy ok`.

> **Про `python3` дальше по тексту.** Все команды в этой инструкции написаны
> через `python3`: на macOS 12.3+ и в большинстве дистрибутивов Linux команды
> `python` нет вообще. На Windows наоборот, и там `python3` перекрывает шим из
> `tools/bin` после подключения прослойки (шаг 6). Внутри скриптов проекта это
> уже решено переменной `$RC_PY` из `tools/env.sh` — руками ничего подбирать
> не надо.

## Шаг 2. Распознавание речи (whisper.cpp + модель)

Модель — `large-v3-turbo`, **1,5 ГБ**, качается один раз. Предупреди про объём.

**macOS:**

```bash
brew install whisper-cpp        # даёт команду whisper-cli
mkdir -p ~/.cache/whisper-models
curl -L --progress-bar \
  -o ~/.cache/whisper-models/ggml-large-v3-turbo.bin \
  https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-large-v3-turbo.bin
```

**Linux** (в apt пакета нет, собираем — 3–5 минут):

```bash
git clone https://github.com/ggml-org/whisper.cpp /tmp/whisper.cpp
cmake -B /tmp/whisper.cpp/build -S /tmp/whisper.cpp -DCMAKE_BUILD_TYPE=Release
cmake --build /tmp/whisper.cpp/build --config Release -j
sudo cp /tmp/whisper.cpp/build/bin/whisper-cli /usr/local/bin/
mkdir -p ~/.cache/whisper-models
curl -L --progress-bar \
  -o ~/.cache/whisper-models/ggml-large-v3-turbo.bin \
  https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-large-v3-turbo.bin
```

**Windows:** пропусти этот шаг — whisper и модель ставит `restore-tools.ps1`
на шаге W1, внутрь `tools/`.

Человек хочет полегче — есть `ggml-small.bin` (465 МБ, та же ссылка с другим
именем файла). Скажи честно: на терминах он ошибается заметно чаще, а вычитка
транскрипта потом стоит дороже сэкономленного гигабайта.

Скрипты ищут модель в `$WHISPER_MODELS_DIR` (по умолчанию
`~/.cache/whisper-models`; на Windows прослойка сама укажет на `tools/`).
Нестандартная папка → допиши в профиль оболочки:

```bash
echo 'export WHISPER_MODELS_DIR="/свой/путь"' >> ~/.zshrc   # или ~/.bashrc
```

**Проверка шага:**

```bash
whisper-cli --help | head -3
ls -lh "${WHISPER_MODELS_DIR:-$HOME/.cache/whisper-models}"
```

Отдельный открытый проект (Apache-2.0): карточки приёмов с готовыми
demo-компонентами. Конвейер ссылается на него из `library/index-*.md`, оттуда
же берутся звуковые эффекты.

⚠️ **Клонировать строго в подпапку `skill/`, рядом с проектом.** Upstream
переструктурировали репозиторий — всё переехало в корень, без префикса
`skill/`. Конвейер же ссылается на старые пути `../video-shotcraft/skill/…`.
Клон в подпапку сводит их без единой правки в шести файлах `library/`.

```bash
git clone https://github.com/Vincentwei1021/video-shotcraft ../video-shotcraft/skill
```

⚠️ **Клонируй с историей — без `--depth`.** Общий банк звуковых эффектов
upstream убрал из своего `main` 29.10.2026, и достать его можно только из
истории (шаг 5 делает это сам). У поверхностного клона истории нет, и звука ты
не получишь.

**Проверка шага** (обе папки должны существовать):

```bash
ls ../video-shotcraft/skill/references/shots/ | head
ls ../video-shotcraft/skill/demos/ | head
git -C ../video-shotcraft/skill log --oneline -1   # история на месте
```

Человек уже держит этот репозиторий в другом месте — не клонируй второй раз,
а поправь относительный путь `../video-shotcraft/` на фактический в
`library/INDEX.md`, `library/index-*.md`, `library/components.md`,
`library/energy-arc.md`. Плюс два места вне `library/`, о которых легко забыть:
`scripts/setup-assets.sh` принимает путь к клону первым аргументом, а
`scripts/workbench.sh` берёт стол из переменной `RC_WORKBENCH` — допиши её в
профиль оболочки:

```bash
echo 'export RC_WORKBENCH="/фактический/путь/video-shotcraft/workbench"' >> ~/.zshrc
```

**Windows:** шаг делает `restore-tools.ps1` (W1) — он качает каталог архивом
и раскладывает в `skill/` сам. Отдельно клонировать не нужно.

## Шаг 5. Звуковые банки

В репозитории лежат **описи** банков, но не сами аудиофайлы: эффекты честнее
брать из первоисточника (shotcraft, Apache-2.0), а музыка Mixkit по лицензии
не перевыкладывается отдельными файлами. Скрипт доложит эффекты на место:

```bash
scripts/setup-assets.sh
```

**Что он делает с эффектами и почему это не одна строка.** Upstream 29.10.2026
убрал общий банк из своего `main` и перешёл на подбор под конкретный ролик с
Freesound. Поэтому скрипт идёт по трём путям, сверху вниз:

1. банк лежит в клоне файлами (старый снимок) — просто копирует 106 файлов по
   описи `SFX-FILES.txt`;
2. клон с историей — достаёт банк из коммита `5a2e98da`, последнего, где он
   на месте, через `git show` (рабочее дерево клона не трогает);
3. ни то ни другое — печатает оба способа получить звук и **не делает вид, что
   звук установлен**.

⚠️ **Скажи человеку честно одну вещь:** происхождение части этих эффектов
upstream сам не смог подтвердить (его `assets/audio/ATTRIBUTION.md`), и это
причина, по которой он от банка отказался. Для монетизируемых роликов — либо
сверка по ATTRIBUTION, либо свой подбор через их
`assets/scripts/sfx-source.py` (по умолчанию CC0). Имена тогда разойдутся с
описью, и опись пересобирается: `scripts/sfx-catalog.sh`.

**Музыку человек скачивает сам:** 4–5 бесплатных треков с
[mixkit.co](https://mixkit.co/free-stock-music/), кладёт в
`engine/public/shared/bgm/` и дописывает строкой в `INDEX.md` рядом.
Характеры и названия треков, на которых собран конвейер, — в том же INDEX.

Почему именно 4–5, а не один: без них не работает правило анти-повтора —
соседние ролики не должны идти под одну музыку.

⚠️ **Метаданные у файлов Mixkit пустые.** Название и ссылку надо записывать
в момент скачивания, иначе через неделю никто не вспомнит, что это за трек.

**Проверка шага:**

```bash
find engine/public/shared/sfx -name '*.mp3' | wc -l   # ожидается 106
find engine/public/shared/bgm -name '*.mp3' | wc -l   # ожидается 4-5
```

Эффектов меньше 106 — смотри, что напечатал скрипт: он называет, какой из трёх
путей сработал и чего не хватило. Ноль эффектов — конвейер собирать можно, но
ролик выйдет без звуковых акцентов; это надо сказать человеку сейчас, а не
когда он услышит результат.

## Шаг 6. Прослойка окружения

Скрипты конвейера подключают `tools/env.sh` — он собирает окружение под
текущую ОС (на Windows подставляет инструменты из `tools/` и шимы, на macOS и
Linux почти ничего не делает). Путь внутри скриптов **не зашит**, считается от
самого скрипта, поэтому проект переносится на любую машину как есть.

**Проверка шага:**

```bash
. ./tools/env.sh && echo "root=$RC_ROOT" && which ffmpeg
```

Печатается корень проекта и путь к ffmpeg. Если `RC_ROOT` пустой —
проверь, что `tools/env.sh` на месте и у него права на чтение.

Накатывал обновление базового комплекта поверх проекта → строка подключения
в скриптах могла затереться. Вернуть её — одна строка на скрипт, перечень и
форма записи: `tools/WINDOWS.md`.

## Ветка W. Только Windows

Выполняется **между шагом 1 и шагом 4** вместо шагов 2, 3 и 5.

### W1. Инструментарий внутрь проекта

```powershell
powershell -ExecutionPolicy Bypass -File tools\restore-tools.ps1
```

Качает и раскладывает в `tools/`: ffmpeg, whisper-cli с бэкендами, модель
`large-v3-turbo` (1,6 ГБ), каталог приёмов video-shotcraft в `skill/`, ставит
зависимости движка и звуковые эффекты. **Идемпотентен** — что уже стоит,
пропускает, так что прерванный запуск можно просто повторить.

Почему внутрь проекта, а не в систему: на `C:\` обычно нет прав записи, а
системный PATH трогать незачем. Плюс бинарники не уходят в git — GitHub не
принимает файлы больше 100 МБ, а здесь ffmpeg 217 МБ и модель 1,6 ГБ.

**Проверка шага:**

```bash
. ./tools/env.sh && which ffmpeg whisper-cli python3 head caffeinate
ls -lh tools/whisper-models/
```

Все пять команд должны разрешиться в `tools/`, модель — около 1,5 ГБ.

### W2. Зачем нужны шимы (объясни человеку, если спросит)

| Шим | Что чинит |
|---|---|
| `head` | в этой сборке Git Bash (минимальный MSYS) `head` отсутствует вообще, а скрипты базового комплекта его зовут |
| `python3` | в Windows-PATH `python3` — заглушка Microsoft Store: печатает «Python» и выходит. Настоящий интерпретатор зовётся `python` |
| `caffeinate` | macOS-утилита «не давать машине уснуть во время рендера». Съедает свои флаги и запускает команду как есть |

Плюс прослойка задаёт `PYTHONIOENCODING=utf-8`: Python под Windows пишет в
консоль в cp1251 и падает с `UnicodeEncodeError` на символах «×», «→», «✓»
в выводе скриптов QA.

### W3. Патчи монтажного стола

⚠️ **Самое важное место всей установки на Windows, и его легко пропустить.**

Монтажный стол (доводка готового ролика без правки кода) живёт **в клоне
shotcraft**, а клон целиком в `.gitignore`. Значит правки ниже **не приезжают
с кодом конвейера** — агент накладывает их сам, и заново после каждого
обновления клона.

Все пути ниже — от `../video-shotcraft/skill/workbench`.

**1. Зависимости стола**

```bash
cd ../video-shotcraft/skill/workbench
npm install --ignore-scripts
npm install --ignore-scripts --save-exact \
  @remotion/layout-utils@4.0.484 @remotion/paths@4.0.484 \
  @remotion/transitions@4.0.484 @remotion/lottie@4.0.484 \
  @remotion/fonts@4.0.484 lottie-web@5.13.0
```

Версии добавочных пакетов держать **равными версии стола** (4.0.484), а не
движка: иначе в сборку приедут два экземпляра remotion. Проверь фактическую
версию стола в его `package.json` и подставь её, если она другая.

**2. Симлинк `demosrc`**

В репозитории это относительный симлинк на `../demos` — через него библиотека
приёмов попадает в стол. Распаковка из архива превращает его в обычный файл со
строкой `../demos` внутри, и генератор индекса падает с `ENOTDIR`:

```bash
rm demosrc && node -e "require('fs').symlinkSync('../demos','demosrc','junction')"
```

**3. Нормализация путей в `scripts/gen-index.mjs`**

`relative()` на Windows отдаёт путь с обратными слэшами, и он уходит прямо в
текст импорта: `from "@demos/outro\ui-strip-away-outro\…"`. esbuild читает
`\u` как escape-последовательность и валит vite на старте с `Syntax error "i"`
— причём не на сборке индекса, а позже, при сканировании зависимостей, так что
сообщение указывает совсем не туда. Тот же путь ниже режется по `/` на
категорию и слог, то есть без правки ломаются ещё и длительности карточек.

Найди строку с `relative(demosDir, p)` и приведи к виду:

```js
const rel = relative(demosDir, p).replace(/\.tsx$/, "").split(sep).join("/");
```

Плюс добавь `sep` в импорт из `node:path`. Помечай правку комментарием
`ПРАВКА reelcraft (Windows)` — чтобы через месяц было понятно, откуда она.

**4. Битый симлинк `public/cardpreviews`**

Ведёт в `gallery/media` — превью карточек, которые качаются отдельно. Пока их
нет, симлинк битый, и на Windows chokidar валит весь dev server с
`EBUSY: resource busy or locked, scandir`. Vite при этом успевает написать
«ready», и сообщение уводит в сторону. Лечение двойное:

```bash
mkdir -p ../gallery/media
```

и в `vite.config.ts`, в блок `server`, добавить исключения из watcher:

```ts
watch: { ignored: ["**/public/cardpreviews/**", "**/public/sfxlib/**", "**/public/bgmlib/**"] },
```

**5. Vite слушает только `::1`**

Без явного `host` vite поднимается на IPv6-петле, а лаунчер ждёт сервер через
`fetch('http://localhost:5198')` — Node резолвит `localhost` в 127.0.0.1 и
получает отказ. Сервер при этом работает и в браузере открывается, но лаунчер
каждый раз сообщает «не поднялся за 90с» и уводит на поиск несуществующей
ошибки. В тот же блок `server`:

```ts
host: "127.0.0.1", port: 5198, strictPort: true,
```

**6. Экспорт MP4 из стола — две правки в `vite.config.ts`**

| Было в комплекте | Почему не работает на Windows | Стало |
|---|---|---|
| `spawn("rsync", ["-aL", …])` | rsync на Windows нет, и шимом не обойтись: Node не запускает `.cmd`/`.bat` без `shell` | копирование через `fs.cp({recursive, dereference})` + `rm` — тот же смысл, что `-aL --delete` |
| `spawn(path.join(…, ".bin", "remotion"))` | `.bin/remotion` на Windows — shell-обёртка, `spawn` её не исполнит | тот же путь `+ ".cmd"` под win32 |

Без первой правки экспорт падает на синхронизации, без второй — на запуске
рендера. Предпросмотр и правка клипов работают и без них, так что если человек
торопится — эти две можно отложить, но скажи ему, что экспорт пока не работает.

**7. Чего НЕ чинить**

`open.mjs` опознаёт свой dev server через `ps` и на Windows сознательно
возвращает «не мой», поэтому старый сервер не гасит — при смене ролика стол
остался бы на предыдущем. Гасит лаунчер проекта `scripts/workbench.sh` (через
WMI). Сам `open.mjs` не трогай: он приходит с обновлением базового комплекта,
и правка потеряется.

**Проверка ветки W:**

```bash
cd ../video-shotcraft/skill/workbench && npx vite --version
cd - && bash scripts/workbench.sh --stop   # лаунчер отвечает, а не падает
```

## Шаг 7. Константы канала (данные от человека)

Спроси **одним блоком**, не по одному вопросу:

1. **Хендл канала** — как подписывать финальную карточку, например `@my_channel`.
2. **Слоган** — строка под хендлом, 3–5 слов: о чём канал.
3. **Круглый аватар канала** — PNG с прозрачностью, обрезанный по кругу.
   Это **основной** пруф финального кадра: режим по умолчанию
   `proofMode='profile'` рисует именно его. В комплекте лежит серая заглушка —
   рендер с ней проходит, но в ролик такое не выпускают.
4. **Скрин канала** — путь к картинке с шапкой (видно название и число
   подписчиков). Запасной пруф, режим `'image'`. Нет скрина — пусть
   сделает сейчас, это минута.
5. **Имя канала** так, как оно стоит в шапке.
6. **Число подписчиков** строкой, например «1 200 подписчиков». Берётся
   настоящее. Выдумывать запрещено (правило 17) — и это не формальность:
   выдуманный пруф в кадре отличается от настоящего, зрители это читают.
7. **Куда складывать готовые ролики** — папка, например `~/Desktop/Ролики`.
   Держи её **вне репозитория**: 10–30 МБ на ролик.
8. **Язык записи** — русский по умолчанию; другой → значение для `WHISPER_LANG`.

Дальше сделай сам:

- Впиши ответы в `engine/src/channel.ts` — файл размечен комментариями.
  Папка вывода там стоит как `CHANGE_ME/путь/к/папке/роликов` — замени.
- Положи **аватар** в `engine/public/shared/cta/avatar.png`, **скрин шапки** —
  в `engine/public/shared/cta/tg-channel.jpg`, оба вместо серых заглушек.
  **Померь пропорции скрина и пропиши `ctaProofAspect`** (высота/ширина) —
  иначе картинка в карточке растянется.
- Создай папку вывода, если её нет.
- Не русская речь → допиши `WHISPER_LANG` в профиль оболочки.

**Проверка шага** — не «на глаз», а командой: в `engine/src/channel.ts` не
осталось заглушек, и обе картинки CTA — уже свои, а не серые:

```bash
grep -nE "your_channel|О чём твой канал|CHANGE_ME" engine/src/channel.ts   # пусто
grep -la "ЗАГЛУШКА" engine/public/shared/cta/*                             # пусто
```

Заглушек нет вовсе (человек их удалил) — верни их, иначе рендер карточки
упадёт на отсутствующем файле:

```bash
python3 tools/make-placeholder-cta.py
```

### Если подписчиков пока мало

Счётчик в карточке можно не показывать — это решение, а не поломка: пруф с
числом «4» работает против канала. Спроси человека и, если он согласен,
выключи показ числа, оставив имя и хендл.

## Шаг 8. Оформление: персонаж или тёмная тема

Тема по умолчанию — светлая: снизу кадра стоит нарисованный персонаж и
«играет» позами под речь. В репозитории лежат **нейтральные серые
силуэты-заглушки** — движок с ними запускается и контрольный рендер проходит,
но в ролик такое не выпустишь.

Заглушки при необходимости перерисовываются заново:
`python3 tools/make-placeholder-poses.py` (нужен Pillow).

Спроси человека, как он хочет.

**(а) Свой персонаж** — основной путь. Нужно 10 файлов PNG **с прозрачным
фоном**, один персонаж в одном стиле, разные позы, имена ровно такие —
движок ищет по ним:

```
pose-base.png  pose-welcome.png  pose-wave.png  pose-present-left.png
pose-present-right.png  pose-think-chin.png  pose-think-cross.png
pose-shrug.png  pose-stop.png  pose-fists.png
```

Требования: одинаковый рост фигуры на всех позах (иначе персонаж «прыгает»
при смене), фигура по центру, размер около 1056×1140, без теней на фоне.
Что означает каждая поза — `engine/public/shared/character/README.md`.

**Выбрал (а) — не оставляй человека одного на этом шаге, предложи помощь и
веди его.** Готовый промпт с подстановками лежит в
`library/character-prompt.md`, работай по нему:

1. Скажи, что персонаж — это он сам, и попроси фронтальное фото и 5–7 слов
   о внешности (форма лица, причёска, борода, очки).
2. Спроси два-три цвета одежды. Предложи взять их из палитры выбранной темы
   (`library/light-theme.md`), чтобы персонаж не спорил с кадром.
3. Собери промпт эталонной позы `base` и отдай человеку — генерировать он
   будет в своей рисующей нейросети, у агента её нет.
4. **Дождись, пока он утвердит эталон.** Дальше каждая следующая поза
   генерится с приложением утверждённого `pose-base.png` как референса.
   ⚠️ Одной пачкой все десять не генерить: от позы к позе уплывут лицо,
   одежда и рост, а движок переключает позы встык — в кадре это выглядит как
   разные люди. Переделывать придётся все десять.
5. Когда картинки готовы — доделай сам: вырежи фон
   (`python3 tools/character-cutout.py <папка>`), приведи все десять к
   1056×1140 по макушке и центру, положи в
   `engine/public/shared/character/` под точными именами.
6. Отрендери `DemoLight` и покажи, как персонаж стоит в реальном кадре.

⚠️ **Посмотри готовые позы глазами, все десять.** Лишние пальцы и обрезанные
кисти генерация выдаёт регулярно, а в кадре это замечают сразу. Проверь ещё
одинаковый рост: положи две позы рядом, макушка и линия плеч должны стоять на
одной высоте.

**(б) Без персонажа** — тогда основная тема тёмная, её правила в
`library/adaptive-theme.md`. Заглушки можно оставить, они ни на что не влияют.
Это нормальный выбор, а не упрощение: тёмные темы в конвейере полноценные.

**Проверка шага:** открой любой `pose-*.png` и убедись глазами, что это
персонаж человека, фон прозрачный, фигура не обрезана. Либо человек выбрал
(б) — тогда проверь, что тема по умолчанию переключена.

## Шаг 9. Установи скилл

Скилл — инструкция агенту «как собирать ролик от начала до конца».

```bash
mkdir -p ~/.claude/skills/reelcraft
cp SKILL.md ~/.claude/skills/reelcraft/SKILL.md
```

**Теперь обязательный шаг, без которого скилл нерабочий.** В скопированном
файле есть строка `Проект: <ПУТЬ_К_ПРОЕКТУ>`. Скилл лежит в домашней папке, а
не в репозитории, — и пока в этой строке плейсхолдер, агент в новой сессии не
знает, где искать конвейер:

```bash
sed -i.bak "s|<ПУТЬ_К_ПРОЕКТУ>|$(pwd)|" ~/.claude/skills/reelcraft/SKILL.md
grep -n "^Проект:" ~/.claude/skills/reelcraft/SKILL.md   # должен быть реальный путь
```

(на macOS `sed -i.bak` — именно с суффиксом, иначе BSD sed ругается; `.bak`
потом можно удалить)

Рядом лежит второй скилл — `reels-radar`, поиск тем по чужим залетевшим
роликам. Он самостоятельный, конвейера не требует и ставится так же:

```bash
mkdir -p ~/.claude/skills/reels-radar
cp .claude/skills/reels-radar/SKILL.md ~/.claude/skills/reels-radar/SKILL.md
```

Радару нужен токен Apify — скопируй `.env.example` в `.env` и подскажи, где
его взять. Без токена радар не работает, но на сборку роликов это не влияет.

**Проверка шага:** в новой сессии агента скиллы `reelcraft` и `reels-radar`
видны в списке доступных, и в `reelcraft` строка `Проект:` ведёт на реальную
папку.

### Работаешь в Codex, а не в Claude Code

Тогда скиллы в домашнюю папку копировать не нужно: `AGENTS.md` в корне проекта
Codex читает сам, а его навыки, субагенты и образец конфигурации лежат в
`.codex/`. Порядок установки и что в конфигурации обязательно поправить под
себя (модель и папка вывода) — `.codex/README.md`. Прочитай с человеком блок
постоянных разрешений: он даёт агенту работать без вопросов всю сборку, и это
его решение, а не настройка по умолчанию.

## Шаг 9а. Аккаунты-доноры для радара тем

Радар отвечает на вопрос «о чём снимать». Он считает, насколько ролик обошёл
медиану **своего же аккаунта**, поэтому без списка аккаунтов он не работает
вообще — а в комплекте лежат только примеры формата
(`example_account_1…3` в `radar/accounts.json`).

**Скажи человеку прямо: этот список он должен собрать сам, за него это сделать
нельзя.** Чужие доноры дадут чужие темы.

Что объяснить, прежде чем он пойдёт искать:

- **Нужно 4–6 аккаунтов своей ниши.** Меньше — шортлист пустой, больше — счёт
  за выгрузку растёт без пользы.
- **Аккаунт должен регулярно публиковать короткие ролики и иметь историю.**
  Радар считает выброс относительно медианы самого аккаунта: у кого три
  ролика за год, у того медианы нет, и он только шумит.
- **Брать не самых больших, а самых близких по теме.** Медианы у аккаунтов
  разного размера несопоставимы, и миллионник заглушит остальных.
- **Это доноры тем, а не образцы для копирования.** Радар отдаёт тему и форму
  хука. Текст, примеры и подача — его. Пересказ чужого ролика аудитория
  считывает мгновенно.

Как помочь, не делая выбор за него: попроси назвать 3–5 авторов, которых он
сам смотрит по своей теме, и впиши их. Это честнее, чем подбирать наугад.

Записывается в `radar/accounts.json`, поле `note` — для себя, радар его не
читает:

```json
"accounts": [
  { "username": "ник_без_собачки", "note": "о чём аккаунт, язык" }
]
```

Пороги `min_outlier`, `min_views` и `max_per_account` в том же файле —
стартовые. Предупреди, что их настраивают после двух-трёх прогонов на своей
нише, а не переносят чужие.

**Проверка шага:** в `radar/accounts.json` нет ни одного `example_account`, и
`python3 radar/fetch.py --dry` печатает запрос с его аккаунтами, ничего не
отправляя. Разбор метрики и расходов — `radar/README.md`.

## Шаг 9б. Профиль автора — чтобы ролики звучали как он

Конвейер пишет сценарий сам. Без профиля он напишет его «средним голосом», и
это самое заметное отличие чужого ролика от своего: механика одинаковая, а
слышно, что говорит не человек.

В комплекте лежит скилл, который берёт интервью и собирает профиль из семи
заметок: кто он, что ценит, куда идёт, в чём силён, как работает и — главное
для роликов — **как он говорит**.

```bash
mkdir -p ~/.claude/skills/profile
cp .claude/skills/profile/SKILL.md ~/.claude/skills/profile/SKILL.md
```

Дальше, в новой сессии: «давай профиль».

Что сказать человеку, чтобы он не отложил это «на потом»:

- **Это разговор, а не анкета.** Скилл задаёт по одному вопросу за раз и сам
  собирает из ответов заметку. Одна сфера за сессию — дальше внимание садится.
- **Для роликов важнее всего заметка `voice`** — как звучит его текст наружу.
  Если время есть только на одну, брать её.
- **Профиль живёт не внутри конвейера**, а в его рабочей папке или волте
  Obsidian: его читают и другие агенты, не только сборка роликов.

**Проверка шага:** скилл `profile` виден в новой сессии, и в папке профиля
появился хотя бы `voice.md`. Полностью проходить интервью до первого ролика не
обязательно — но сценарий без `voice` будет пресным, и это надо сказать вслух,
а не умолчать.

## Шаг 11. Первый ролик

Объясни человеку порядок и пройди его вместе с ним:

1. Он записывает голос **40–60 секунд** на тему, где есть что показать на
   экране: сервис, репозиторий, своя папка проекта. Файл кладёт в `inbox/`.
2. `./prep.sh` — обработка звука (нормализация громкости и ускорение речи).
3. `scripts/queue-add.sh inbox/<имя>-prep.mp4 01` — заводит слот с номером 01.
4. Дальше он говорит агенту: **«Собери ролик 01 через reelcraft»** — и агент
   работает по скиллу: вычитывает транскрипт, пишет сториборд, верстает
   сцены, гоняет QA, рендерит.

Что понадобится по ходу — предупреди **заранее**, а не когда упрётесь:

- **Живой экран обязателен** (правило 27): в ролике должен быть хотя бы один
  настоящий скриншот или запись экрана с наездом камеры. Пусть человек заранее
  снимет то, о чём говорит, и положит в `inbox/screenshots/` или
  `footage/clips/` (плюс строка в `footage/catalog.md`).
- **Иконки брендов**, которые звучат в речи, докачиваются командой
  `node scripts/fetch-icons.mjs <названия>` — агент сделает это сам.
- **Звук под конкретный микрофон настраивается замером, а не на глаз.** Цепочка
  в `prep.sh` собрана под один тип записи. Сменил микрофон — сделай тестовую
  запись 30–40 секунд обычной речи в той же комнате и настрой фильтры по
  спектру. Угадывать тут бессмысленно.

### Про темп, чтобы не было разочарования

Скажи человеку прямо: **ролик собирается штучно.** Под каждый сценарий
верстается 8–12 сцен, творческая часть идёт на основной модели. Реалистично
**4–8 роликов в месяц**, а не 30 за вечер. Конвейер снимает монтаж и
оформление, но не придумывание.

|---|---|
| Скрипт падает на второй строке, не найден `env.sh` | Запущен не из проекта либо `tools/env.sh` отсутствует. Путь считается от скрипта — проверь, что файл на месте |
| `✗ Нет модели whisper` | Модель не там, где ищет скрипт → задай `WHISPER_MODELS_DIR` (шаг 2) |
| `✗ Нет whisper-cli` | macOS: `brew install whisper-cpp`. Linux: шаг 2, сборка. Windows: W1 |
| `python3` печатает «Python» и выходит | Заглушка Microsoft Store. На Windows это чинит шим в `tools/bin` — подключи прослойку (шаг 6) |
| `python: command not found` на macOS или Linux | Там есть только `python3`. В скриптах проекта зовётся `$RC_PY` из прослойки; если команда твоя — пиши `python3` |
| `ModuleNotFoundError: numpy` при замерах звука | Шаг 1: `python3 -m pip install --user Pillow numpy` |
| `✗ Не нашёл ни банк SFX, ни git-клон` | Каталог приёмов склонирован поверхностно (`--depth`) или положен архивом: банк живёт в истории. Переклонируй с историей (шаг 3) и повтори `scripts/setup-assets.sh` |
| Рендер падает на `shared/cta/avatar.png` | Заглушки CTA удалены, свои не положены. Либо положи свои (шаг 7), либо верни заглушки: `python3 tools/make-placeholder-cta.py` |
| Ролик собрался, но без звуковых акцентов | Банк SFX не установлен — смотри вывод `scripts/setup-assets.sh` (шаг 5) |
| Скилл `reelcraft` есть, но агент не находит проект | В `~/.claude/skills/reelcraft/SKILL.md` осталась строка `Проект: <ПУТЬ_К_ПРОЕКТУ>` — впиши абсолютный путь (шаг 9) |
| `UnicodeEncodeError` в выводе QA | Не подключена прослойка: она задаёт `PYTHONIOENCODING=utf-8` |
| `head: command not found` | То же: шим `head` живёт в `tools/bin` |
| Рендер «висит» на первом запуске | Докачивается headless-браузер ~93 МБ — дать доработать |
| Шрифты не грузятся / рендер падает по таймауту | Шрифты только локальные; `@remotion/google-fonts` в этом проекте запрещён |
| Линт ругается на `Math.random` / `Date.now` | Рендер многопоточный: случайность только через `mulberry32` из `src/lib/helpers.ts` |
| Субтитры налезают на картинку | Караоке-полоса темы неприкосновенна, границы — в спеке темы |
| Персонаж «двоится» при смене поз | `<Character swapMode="dip">`, не `fade` |
| Картинка в наезде уезжает вправо и вверх | У `PageCam` в вертикали задавать явно `viewportW={1080} viewportH={1920}` |
| Пустой низ кадра, «дырка» под контентом | Правило 20: контент до ~1400 или персонаж закрывает низ |
| Монтажный стол: `Syntax error "i"` на старте vite | Не наложена правка 3 ветки W (обратные слэши в путях импорта) |
| Монтажный стол: `EBUSY … scandir` | Не наложена правка 4 ветки W (битый симлинк превью) |
| Монтажный стол: «не поднялся за 90с», но в браузере открыт | Не наложена правка 5 ветки W (vite слушает только `::1`) |
| Экспорт из стола падает | Не наложены правки 6 ветки W (rsync и `.bin/remotion`) |

Дальше всё нужное — в `CLAUDE.md` (нормы конвейера) и `SKILL.md` (порядок
сборки ролика). Почему Windows-слой устроен именно так — `tools/WINDOWS.md`.
