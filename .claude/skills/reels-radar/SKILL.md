# Reels-radar — чужие залетевшие ролики → очередь своих тем

Проект: **корень этого репозитория**, все команды — из него, в Git Bash.
Замысел и обоснование метрики — `docs/РАДАР-ПЛАН.md`, прочитать при первом
запуске. Этот файл — порядок работы.

**Что радар делает и чего не делает.** Он отдаёт **тему и форму хука**. Текст,
примеры, подача и угол — наши. Позиционирование автора стоит на «я сам
наступил, вот мой результат»; пересказ чужого ролика ломает его мгновенно и
считывается аудиторией. Это не стилистическое пожелание, а граница.

## Перед первым шагом прочитать

| Что | Где |
|---|---|
| Публичный голос | твой файл голоса |
| Позиционирование | твой файл позиционирования |

Без `positioning.md` шаг 5 (отсев не наших тем) выполнить нельзя — не угадывай.

## Правило повторов

**Пробовать до 5 раз, и только потом звать автора** (его правило от 2026-10-02).
Это зашито в `radar/run.sh`, отдельной дисциплины не требует — но помнить, что
повтор здесь **платный**: протухшие ссылки чинятся только новой выгрузкой
Apify, ~$0.4 за попытку.

Обычный запуск всего цикла — одной командой:

```bash
bash radar/run.sh 8                 # до 8 кандидатов, до 5 попыток
bash radar/run.sh 8 --attempts 2    # если не хочется тратить на повторы
bash radar/run.sh --attempts 0      # бесплатно: показать, чего не хватает
```

Шаги 1–3 ниже — что `run.sh` делает внутри; по отдельности они нужны, когда
что-то идёт не так.

## Шаг 1. Выгрузка — платный шаг, предупредить

Apify берёт примерно $2–3 за 1000 результатов. Прогон 5 аккаунтов × 30 постов
— это около 150 результатов, то есть центы, но **счёт идёт на реальные деньги
и данные уходят во внешний сервис**. Перед запуском сказать автору, сколько
результатов будет, и дождаться «ок». Посмотреть запрос, ничего не отправляя:

```bash
python radar/fetch.py --dry
```

Боевой прогон:

```bash
python radar/fetch.py                 # окно и лимиты из radar/accounts.json
python radar/fetch.py --days 30 --limit 20   # если нужен прогон подешевле
```

Токен берётся из `reelcraft/.env` (в git не попадает). Нет токена — скрипт
скажет прямо.

## Шаг 2. Отбор по метрике

```bash
python radar/rank.py
```

Считает по каждому аккаунту медиану просмотров и коэффициент выброса
(просмотры ÷ медиана). Кандидат обязан пройти **оба** порога:

- относительный — выброс ≥ 3× (тема обошла собственную ленту аккаунта);
- абсолютный — ≥ 5000 просмотров (её вообще увидело живое количество людей).

Почему оба. Сырые просмотры несравнимы между аккаунтами: 100 000 у автора с
двумя миллионами подписчиков — провал, 20 000 у автора с пятью тысячами —
попадание. Но и один коэффициент врёт: у спящего аккаунта медиана бывает 500,
и ролик на 1700 даст «выброс 3.4×», хотя это шум. Плюс потолок в 5 роликов на
аккаунт, чтобы один донор с удачным месяцем не занял весь шортлист.

Результат читать глазами: `radar/out/shortlist.md`. Пометка ⚠️ в колонке
«Грубо» — метрика посчитана по лайкам или медиана стоит на малом числе
роликов; такого кандидата проверять внимательнее.

## Шаг 3. Скачивание и расшифровка

```bash
bash radar/pull.sh 8        # верхние 8 кандидатов
```

Запускать **сразу после шага 1**: прямые ссылки на видео живут меньше часа,
дальше CDN отдаёт 403. Повтором занимается `run.sh`, руками шаг 1 перезапускать
не нужно.

Часть ссылок приходит DASH-дорожкой без звука. Такие кандидаты записываются в
`radar/out/_noaudio.txt` и в повторах больше не участвуют: новая выгрузка
их не починит, а каждая попытка стоит денег. Это нормальный исход, не поломка.

Расшифровка идёт локальным whisper: бесплатно и никуда не уходит. Тексты —
`radar/out/clips/<account>-<shortCode>.txt`.

Текст в пару слов («*Gunshot*», «*Music*») — не сбой: ролик чисто визуальный,
речи в нём нет. Радар по аудио такие не читает, тему по ним не придумывать —
отправлять в отсев с этой пометкой.

## Шаг 4. Разбор — это делает модель, не скрипт

По каждому расшифрованному ролику собрать карточку темы. Не ссылку, а разбор:

```
Тема:      «3 промпта, которые заменяют джуна»
Метрика:   47 000 при медиане 9 000 → 5,2×
Хук:       «Я перестал платить фрилансеру 30 тысяч» — цифра + личная потеря
Структура: проблема → 3 примера на экране → результат → CTA
Наш угол:  то же на n8n + Claude, со скриншотом реального сценария
Подходит:  «новички в ИИ» + есть что показать на экране (правило 27)
```

Поле «Хук» — первые 3 секунды дословно плюс одной строкой, **почему** это
работает. Поле «Наш угол» — обязательное: если своего угла нет, тема не наша,
её выкидываем, а не берём «как есть».

## Шаг 5. Отсев

Выкинуть тему, если выполняется хоть одно:

- не про AI, автоматизацию или путь новичка (`positioning.md`);
- нечего показать на экране — правило 27 в `CLAUDE.md` требует живого экрана;
- опирается на цифры и кейсы, которых у автора нет (правило 17: выдумывать
  числа запрещено);
- уже выпускали похожее — сверить по `content/shorts/_index.md`;
- требует раскрыть основную работу автора (она не публична — память
  `privatnost-osnovnoy-raboty`).

## Шаг 6. Запись очереди и ✋ остановка

Карточки дописать в свою очередь тем — новые
сверху, с датой прогона. Старые не удалять: невзятая тема через месяц
нередко оказывается лучше свежей.

Дальше **остановиться и показать автору список**. Выбор тем — его, модель не
решает за него и не запускает сценарий сама. Выбранная тема заводится строкой
в `content/shorts/_index.md` со статусом 🟡.

Следующий шаг после выбора — `/reels-script NN`, не `/reelcraft`: сначала
сценарий под его голос, потом запись, и только потом сборка.
